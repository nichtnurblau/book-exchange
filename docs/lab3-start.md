# Лабораторная №3: первый этап

Реализованы только Ф1 «Регистрация» и Ф2 «Вход и выход» из раздела 4.1 README и ТЗ.
Каталог, объявления и заявки Ф3–Ф10 пока не реализованы.

## Запуск

Нужен Python 3.11 или новее. В терминале из корня проекта:

```bash
python src/main.py
```

В Windows при необходимости используйте `py -3 src/main.py`, в Linux — `python3 src/main.py`.
Запускайте в обычном терминале: ввод пароля через `getpass` скрыт, символы и звёздочки не отображаются.
Нажмите Enter после ввода. Консоль вывода некоторых IDE не поддерживает скрытый ввод.

Установка библиотек, сервер, браузер и база данных для этой команды не нужны.
Все записи хранятся в словаре до завершения процесса. Выход из учётной записи
сохраняет записи в памяти, закрытие программы уничтожает их.

## Что проверить вручную

1. Выбрать 1 и зарегистрировать вымышленного пользователя:
   логин `Reader_1`, пароль `testpass123`, имя `Читатель`, город `Волгоград`,
   контакт `reader@example.test`.
2. Повторить регистрацию с логином `READER_1`: получить ошибку занятого логина.
3. Выбрать 2 и ввести неверный пароль: остаться гостем.
4. Войти с логином `reader_1` и правильным паролем: увидеть имя пользователя.
5. Выбрать 3: увидеть свою учётную запись. Это проверка сессии в рамках Ф2,
   а не отдельная функция управления профилем.
6. Выбрать 4, затем вручную ввести 3: получить «Сначала войдите».
7. Снова войти: запись ещё существует. Выбрать 0 и повторно запустить программу:
   вход больше не работает, нужно зарегистрироваться заново.
8. При регистрации попробовать пустое имя, кириллицу в логине и короткий пароль:
   получить сообщения об ошибках, программа продолжает работу.

## ООП и SOLID

- `User` описывает данные. `InMemoryUserRepository` хранит их.
  `PasswordHasher` работает с паролями. `AuthService` реализует Ф1–Ф2.
  `ConsoleApp` читает и выводит текст. У каждого класса отдельная задача (SRP).
- Сервис получает хранилище извне через небольшой `UserRepository` (DIP, ISP).
  Хранилище можно заменить без переписывания регистрации (OCP).
- Новое хранилище должно сохранять договор: поиск без учёта регистра,
  отсутствие записи — `None`, повторный логин — `ValueError` (LSP).
  Пока есть только одна реализация, множество реализаций не демонстрируется.
- Для хеширования отдельный интерфейс пока не введён: сервис зависит от конкретного
  `PasswordHasher`. Это сознательное упрощение DIP для небольшого первого этапа.
- `main.py` только соединяет объекты и запускает меню.
- Есть аннотации типов и docstring после объявления классов и функций.
  Комментариев внутри алгоритмов нет.

## Пароли и ограничения этапа

Применён PBKDF2-HMAC-SHA256 из `hashlib`, 600 000 итераций, случайная соль
из `secrets` и сравнение через `hmac.compare_digest`. Исходные пароли не хранятся.
Это учебная консольная сессия на одном компьютере, не готовая веб-аутентификация.

README и ТЗ описывают будущую веб-версию с постоянной БД и специализированной
библиотекой хеширования. Для ЛР3 по сообщению преподавателя используются CLI,
InMemory и только стандартная библиотека. Требования веб-версии остаются планом.

## Критерии из Excel

Источник: «СТУДЕНТЫ ИВТ ПРИН 2026(1).xlsx», лист «Лабораторные работы», строка 4.
Функциональные требования Ф1–Ф10 заданы в README и ТЗ, а Excel содержит критерии ЛР3.

| Критерий | Состояние первого этапа |
|---|---|
| 1. Инициализация uv и зависимости | `pyproject.toml` и `uv.lock`; FastAPI, SQLAlchemy, Alembic, Pydantic записаны для следующих этапов |
| 2. Структура проекта | Код в `src`, проверки в `tests`, документы в `docs`; ТЗ перенесён в `docs` |
| 3. Короткая точка входа | `src/main.py` |
| 4. CLI и функциональные требования | Только Ф1 и Ф2; полная лабораторная ещё не завершена |
| 5. SOLID | Разделение обязанностей, договор хранилища, описанное упрощение DIP |
| 6–8. Документация и типизация | Docstring и аннотации типов |
| 9. Ruff | Настройки в `pyproject.toml`, команды ниже |

Для настройки использованы `uv init --bare --name book-exchange --python 3.11`,
`uv add --no-sync fastapi sqlalchemy alembic pydantic`, `uv add --dev --no-sync ruff`.
`--no-sync` записывает зависимости без установки. Исходный код их не импортирует.
Повторно выполнять `uv init` в готовом проекте не нужно.

## Автоматическая проверка

```bash
python -m unittest discover -s tests -v
uvx ruff check src tests
uvx ruff format --check src tests
```

Тесты используют стандартный `unittest`. Ruff является инструментом разработки,
для запуска приложения он не требуется. При первом запуске `uvx` нужен интернет.
