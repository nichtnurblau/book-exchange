# Устройство программы

Программа состоит из моделей, хранилищ, сервисов и консольного интерфейса.
Компоненты создаются и связываются в `src/main.py`.
Объекты хранилищ имеют имена `user_repository`, `book_repository` и
`exchange_repository`; сервисы — `user_service`, `book_service` и т. п.
Имена во множественном числе используются для коллекций записей.
Подготовка схемы и запуск из корня проекта: `uv run alembic upgrade head`,
затем `uv run python -m src.main`.
Импорты собственных модулей начинаются с `src`.

## Структура

| Путь | Содержимое |
|---|---|
| `src/models.py`, `src/book_models.py`, `src/exchange_models.py` | Пользователи, книги, заявки и статусы |
| `src/catalog.py` | `Catalog` и публичная карточка `BookCard` |
| `src/repositories/user.py` | `UserRepository` и `InMemoryUserRepository` |
| `src/repositories/book.py` | `BookRepository` и `InMemoryBookRepository` |
| `src/repositories/exchange.py` | `ExchangeRepository` и `InMemoryExchangeRepository` |
| `src/database/` | ORM-модели, mapper-классы, подключение и граница транзакции |
| `src/database/repositories/` | SQL-реализации трёх репозиториев |
| `migrations/` | История схемы Alembic |
| `src/services/user.py` | `UserService`: регистрация и текущая сессия |
| `src/services/book.py` | `BookService`: управление объявлениями |
| `src/services/exchange.py` | `ExchangeService`: обмены и права участников |
| `src/services/catalog.py` | `CatalogService`: построение актуального каталога |
| `src/menu.py` | `MenuCommand`: номера и названия пунктов меню |
| `src/console_input.py` | `ConsoleInput`: ввод ID и выбор пункта |
| `src/book_cli.py`, `src/exchange_cli.py`, `src/cli.py` | Консольные разделы и общее меню |

В сервисах сначала расположены конструктор и публичные методы, затем методы
с одним нижним подчёркиванием. Такие методы используются внутри класса.


## Модели и хранение

`User` описывает учётную запись, `Book` — объявление о книге, `Exchange` — заявку.
Книги и заявки имеют уникальные числовые идентификаторы, которые выдаёт хранилище.
Записи представлены неизменяемыми dataclass. Для обновления сервис создаёт копию
через `dataclasses.replace`, затем сохраняет её в репозитории.

Основное приложение использует SQLAlchemy-репозитории и общую `Session`.
ORM-записи `UserRecord`, `BookRecord` и `ExchangeRecord` преобразуются в dataclass
через `UserMapper`, `BookMapper` и `ExchangeMapper`. InMemory-репозитории со словарями
сохранены для быстрых модульных проверок, в `src/main.py` они не используются.
База сохраняет данные между запусками.
Удаление книги скрывает объявление, сохраняя сведения для истории заявок.
Пароли хранятся в виде PBKDF2-HMAC-SHA256 с индивидуальной случайной солью.

## Сервисы

| Класс | Назначение |
|---|---|
| UserService | Проверка полей, регистрация и текущая сессия |
| BookService | Создание и изменение объявлений, проверка владельца |
| CatalogService | Получение актуальных карточек из хранилищ и построение Catalog |
| ExchangeService | Заявки, права участников и переходы состояний |

`Catalog` — отдельный объект со снимком карточек. Он отбирает доступные книги,
применяет поиск и фильтры и открывает карточку. Ему не нужны хранилища или сессия.
`CatalogService` получает книги и сведения о владельцах из репозиториев, строит
новый `Catalog` при запросе и передаёт ему условия поиска. Поэтому резервирование
или удаление книги учитывается при следующем запросе.

Консольные классы читают команды и выводят сообщения. Пункты меню описаны
в `MenuCommand` на основе `Enum`. При регистрации каждое поле проверяется сразу;
при ошибке повторяется ввод этого поля. Общие методы `read_id`
и `choose` принадлежат классу `ConsoleInput` и используются в обоих разделах. Проверки прав выполняются
в сервисах, поэтому недопустимое действие запрещено даже при прямом вызове метода.
В публичной карточке есть имя и город владельца. Контакт другого участника
доступен только в принятой или завершённой заявке.

## Правила обмена

Создать предложение можно только для двух доступных книг разных владельцев.
Повторное действующее предложение для той же пары, включая обратное, запрещено.
При принятии обе книги резервируются, а остальные ожидающие заявки к любой из них
отклоняются. После отмены принятой заявки книги освобождаются, подтверждения
сбрасываются. Отклонённые конкурирующие заявки автоматически не восстанавливаются.

Каждый участник подтверждает передачу один раз. После двух подтверждений заявка
завершается, а книги получают статус «Обменена». Закрытые заявки остаются в истории.
Объявление остаётся за исходным владельцем. Для повторного обмена полученной книгой
можно создать новое объявление.

## Принципы проектирования

Модели описывают данные, хранилища отвечают за записи, сервисы — за правила,
консоль — за ввод и вывод. Такое разделение ограничивает обязанности каждого класса.

Сервисы получают хранилища через абстрактные классы на основе `abc.ABC`.
Обязательные методы помечены `@abstractmethod`. InMemory- и SQLAlchemy-реализации явно наследуют
свой базовый класс; неполную реализацию Python не позволяет создать. Новая реализация
должна соблюдать тот же договор: выдавать уникальные ID, возвращать записи и
сообщать об отсутствии записи через ValueError. Это позволяет менять способ
хранения без изменения поиска и основных проверок.

Для консольных классов и PasswordHasher отдельные интерфейсы не введены:
сейчас используется по одной реализации. Это упрощение принципа инверсии зависимостей.

SQL-репозитории находятся в `src/database/repositories` и получают общую `Session`.
Добавление пользователя и новой книги завершается `commit()` в репозитории.
При изменении и удалении объявлений, а также при обменах репозитории вызывают
`flush()`, а `Database.transaction()` сохраняет команду или откатывает её при ошибке.
Изменение заявки и обеих книг выполняется целиком. Подробности связей,
ограничений и миграций приведены в [описании БД](database.md).

## Проверки

Тесты проверяют регистрацию, доступ к данным, поиск, правила обмена, ошибки ввода
и полный консольный сценарий. Для запуска используется стандартный unittest.
Стиль кода проверяется Ruff; настройки находятся в pyproject.toml.
