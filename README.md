## 2\. Назначение программы

### 2.1. Решаемая задача

После прочтения книги часто остаются без использования. Найти человека, которому нужна такая книга и который готов предложить свою, через обычную переписку неудобно: объявления теряются, а доступность приходится уточнять отдельно.

Программа должна объединить объявления в одном каталоге и позволить отправлять предложения об обмене. Ожидаемая польза — повторное использование книг и сокращение времени на поиск подходящего предложения.

### 2.2. Функциональное и эксплуатационное назначение

Платформа предназначена для размещения и поиска объявлений, отправки заявок и учёта результата обмена. Пользователь работает с ней через браузер. Учебная версия демонстрируется на одном компьютере с локально запущенным приложением.

Передача бумажных книг выполняется самими участниками вне приложения. Программа хранит договорённость и её статус, но не организует доставку.

## 3. Описание программы

### 3.1. Общий принцип работы

Пользователь регистрируется, добавляет свои книги и просматривает каталог. Найдя интересующую книгу, он предлагает владельцу одну из своих доступных книг. Владелец принимает или отклоняет заявку. После передачи книг участники отмечают завершение обмена.

Одна заявка относится к обмену одной книги на одну книгу. Объявление описывает один физический экземпляр.

### 3.2. Роли и права доступа

| Роль | Возможности |
|---|---|
| Гость | Просматривать доступные книги и их описания, пользоваться поиском, зарегистрироваться и войти |
| Зарегистрированный пользователь | Возможности гостя, управление своими объявлениями, отправка заявок, просмотр своих входящих и исходящих заявок, принятие и отклонение входящих предложений |

Владелец книги и отправитель заявки — обычные пользователи. Отдельная роль администратора в первой версии не требуется.

### 3.3. Основные страницы

1. **Каталог:** доступные книги, поиск по названию или автору, фильтры по жанру и городу.
2. **Карточка книги:** название, автор, жанр, состояние, описание, город, имя владельца и кнопка предложения обмена.
3. **Регистрация и вход:** формы создания учётной записи и входа в неё.
4. **Мои книги:** список собственных объявлений, добавление, изменение и удаление.
5. **Мои заявки:** входящие и исходящие предложения, их статусы и доступные действия.

### 3.4. Пример использования

1. Анна и Борис создают учётные записи и добавляют по одной книге.
2. Анна находит книгу Бориса и предлагает свою книгу в обмен.
3. Борис видит обе книги во входящей заявке и принимает предложение.
4. Обе книги становятся зарезервированными. Участникам открываются контактные данные друг друга, указанные при регистрации.
5. Анна и Борис договариваются о передаче вне приложения.
6. После передачи каждый подтверждает обмен. Заявка завершается, обе книги получают статус «Обменяна» и исчезают из доступного каталога.

### 3.5. Границы первой версии

В первую версию входят учётные записи, текстовые объявления, каталог, поиск и заявки. Оплата, доставка, встроенный чат, рейтинги, рекомендации, загрузка фотографий и отдельное мобильное приложение не входят в объём проекта.


## 4\. Требования к системе

### 4.1. Функциональные требования

| Код | Функция | Требование |
|-----|---------|------------|
| Ф1 | Регистрация | Пользователь указывает уникальный логин, пароль, отображаемое имя, город и контакт для связи. При занятом логине выводится понятное сообщение |
| Ф2 | Вход и выход | Вход выполняется по логину и паролю. При неверных данных доступ не предоставляется. После выхода действия зарегистрированного пользователя недоступны |
| Ф3 | Добавление книги | Пользователь может создать объявление с названием, автором, жанром, состоянием и описанием. Владелец определяется по текущей учётной записи, начальный статус — «Доступна» |
| Ф4 | Управление книгами | Пользователь может изменять и удалять только свои доступные объявления. Перед удалением требуется подтверждение |
| Ф5 | Каталог и поиск | Каталог показывает доступные книги. Поиск выполняется по части названия или имени автора без учёта регистра, в том числе для русского текста. Фильтры по жанру и городу применяются совместно с поиском. При отсутствии результатов выводится сообщение |
| Ф6 | Отправка заявки | Пользователь выбирает чужую доступную книгу и предлагает одну свою доступную книгу. Заявка сохраняется со статусом «Ожидает ответа» |
| Ф7 | Просмотр заявок | Участники видят свои входящие и исходящие заявки: обе книги, другого участника, дату и статус. Чужие заявки недоступны |
| Ф8 | Ответ на заявку | Владелец запрошенной книги может принять или отклонить ожидающую заявку. При принятии система повторно проверяет доступность обеих книг и резервирует их |
| Ф9 | Отмена | Отправитель может отменить ожидающую заявку. Принятую заявку до завершения может отменить любой из двух участников; книги снова становятся доступными, подтверждения передачи сбрасываются |
| Ф10 | Завершение | Каждый участник принятой заявки может один раз подтвердить передачу. Только после двух подтверждений заявка получает статус «Завершена», а обе книги — «Обменная» |

#### 4.1.1. Входные и выходные данные

 Данные | Состав и ограничения |
|--------|----------------------|
| Учётная запись | Логин: 3–30 латинских букв, цифр или знаков подчёркивания; уникальность проверяется без учёта регистра. Пароль: 8–128 символов. Имя: 1–50 символов. Город: 1–80 символов. Контакт: 1–100 символов, например адрес почты или имя в мессенджере |
| Книга | Название и автор: по 1–150 символов; жанр выбирается из списка «Художественная литература», «Учебная литература», «Научно-популярная литература», «Другое»; состояние — «Новое», «Хорошее» или «Удовлетворительное»; описание необязательно, до 1000 символов |
| Заявка | Ссылки на две книги и двух участников, дата создания, статус и подтверждения передачи. Дата, участники и начальный статус заполняются системой |
| Результат работы | Каталог, карточки книг, собственные объявления, списки заявок и сообщения об успешных действиях или ошибках |

Город объявления берётся из данных владельца. Обязательные текстовые поля, состоящие только из пробелов, не принимаются. Введённые данные 
проверяются на сервере.

#### 4.1.2. Правила обработки заявок

- Нельзя отправить заявку на собственную книгу или предложить чужую книгу.
- Нельзя создать вторую действующую заявку на ту же пару книг, включая обратное предложение. Действующими считаются заявки «Ожидает ответа» и «Принята».
- У книги может быть несколько ожидающих предложений с разными книгами, но только один принятый обмен.
- При принятии заявки обе книги резервируются одновременно. Другие ожидающие заявки, затрагивающие любую из них, автоматически отклоняются.
- Зарезервированные и обмененные книги нельзя редактировать, удалять или предлагать в новой заявке.
- При удалении доступного объявления связанные ожидающие заявки отменяются. Для сохранения истории запись скрывается, а сведения о книге остаются в старых заявках.
- После отмены принятой заявки ранее отклонённые предложения не восстанавливаются: желающие могут создать новые.
- Завершённые, отклонённые и отменённые заявки доступны для просмотра, но не изменяются.

Статусы книги: **«Доступна», «Зарезервирована», «Обменена».**  
Статусы заявки: **«Ожидает ответа», «Принята», «Отклонена», «Отменена», «Завершена».**

### 4.2. Нефункциональные требования

#### 4.2.1. Надёжность и сохранность данных

Данные должны храниться в базе и сохраняться после обычного перезапуска приложения. Ошибочный ввод не должен приводить к закрытию программы или появлению неполных записей.

Изменение статуса заявки и статусов обеих книг должно выполняться одной операцией базы данных: либо сохраняются все изменения, либо ни одно. Это исключает ситуацию, когда зарезервирована только одна книга.

Перед изменением структуры базы разработчик создаёт её резервную копию при остановленном приложении. После повреждения базы восстановление выполняется из последней исправной копии; изменения после её создания могут быть потеряны. Учебная версия не требует круглосуточной работы и автоматического восстановления.

#### 4.2.2. Безопасность

- Пароли хранятся в виде стойких хешей, создаваемых штатными средствами выбранного фреймворка; исходные пароли не сохраняются.
- Сервер проверяет права на каждое изменение объявления или заявки. Подмена адреса страницы или идентификатора записи не должна давать доступ к чужим данным.
- Контакт пользователя виден только второму участнику принятой или завершённой заявки. В публичной карточке выводятся имя и город, без контакта.
- Запросы, изменяющие данные, защищаются от подделки запросов; текст пользователя выводится как текст, без выполнения HTML и скриптов.
- Пароли, секретный ключ приложения и рабочая база с пользовательскими данными не публикуются в GitHub.

#### 4.2.3. Удобство и производительность

Интерфейс должен быть на русском языке, с понятными названиями кнопок. Ошибки ввода должны объяснять, какое поле требуется исправить. Недоступные действия не должны предлагаться пользователю.

Для учебной проверки принимается объём до 100 пользователей, 1000 объявлений и 5 одновременно работающих пользователей. Целевое время открытия каталога и выполнения поиска — не более 3 секунд на компьютере с характеристиками из пункта 4.2.5 при локальном запуске. Это требование к будущей реализации, а не результат уже проведённого измерения.

#### 4.2.4. Условия эксплуатации и обслуживание

Работа выполняется на обычном персональном компьютере в помещении с условиями, указанными производителем оборудования. Специальные требования к температуре и влажности программа не предъявляет.

Пользователю достаточно уметь пользоваться браузером и заполнять формы. Запуск, обновление и резервное копирование выполняет один участник команды, знакомый с установкой Python и запуском приложения.

#### 4.2.5. Технические средства

Для учебной демонстрации принимаются следующие ориентировочные требования: двухъядерный процессор, 4 ГБ оперативной памяти, 1 ГБ свободного места на диске с учётом окружения разработки, клавиатура, мышь и браузер. Приложение и база данных размещаются на одном компьютере. После установки зависимостей локальная демонстрация не должна требовать интернета.

#### 4.2.6. Программная и информационная совместимость

## Технологический стек

Проект будет разрабатываться преимущественно с использованием Python-стека.

Для серверной части планируется использовать:

- **Python** — основной язык программирования.
- **FastAPI** — разработка серверной части и REST API.
- **SQLAlchemy** — проектирование структуры базы данных и работа с ней через Python-код.
- **Pydantic** — описание и валидация данных, передаваемых через REST API.
- **Jinja** — создание динамических HTML-шаблонов.
- **uv** — управление зависимостями и окружением Python.
- **ruff** — проверка качества кода и автоматическое форматирование.

Для хранения данных планируется использовать реляционную СУБД:

- **PostgreSQL или MySQL** — хранение данных о пользователях, книгах и заявках на обмен.
- **asyncpg** — асинхронный драйвер для работы с PostgreSQL, если будет выбрана PostgreSQL.
- **phpMyAdmin** — дополнительный инструмент для просмотра и администрирования базы данных в случае использования MySQL.

Для пользовательского интерфейса базовым вариантом будет:

- **HTML** — структура страниц.
- **CSS** — оформление страниц.
- **Bootstrap** — готовые компоненты интерфейса и адаптивная вёрстка.
- **JavaScript** — дополнительная интерактивность на страницах.

При необходимости пользовательский интерфейс может быть реализован с использованием других frontend-инструментов по выбору участников команды.
Учебный запуск планируется в Windows 11 или Linux. Интерфейс проверяется в Chrome и Firefox на компьютере. Создание отдельного мобильного приложения не требуется.

#### 4.2.7. Передача и хранение программы

Исходный код и документация хранятся в репозитории GitHub. Для передачи допускается ZIP-архив проекта. Версия программы обозначается номером версии в репозитории; специальная физическая упаковка не требуется. Хранение выполняется на исправных цифровых носителях, история изменений сохраняется в Git. Рабочая база и её резервные копии хранятся отдельно от публичного репозитория.

### 4.3. Требования к интеграции

В первой версии интеграции с платёжными системами, службами доставки, почтовыми шлюзами и социальными сетями не предусматриваются. Контакт используется участниками вручную вне приложения.
